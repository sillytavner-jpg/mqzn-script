## Bug 1: LLM 输出被截断

**问题**：调用 `generateRaw()` 时没有设置 `max_tokens` 参数，导致大总结输出被默认值截断，内容不完整。

**修复**：在调用参数中添加 `max_tokens:65536`（对应 Gemini 3.1 Pro 最大输出）。

```diff
- max_chat_history:0,ordered_prompts:
+ max_chat_history:0,max_tokens:65536,ordered_prompts:
```

## Bug 2: 大总结无法回滚

**问题**：Store 中已有 `rollbackSummary()` 函数，但 UI 上没有撤回按钮。且旧版本滚动回后无法恢复最新总结。

**修复方案**（3 处修改）：

### 2a. 添加 summaryHistory 历史记录
在 Store schema 中新增 `summaryHistory` 数组字段，回滚时将弹出的总结暂存于此。

### 2b. 改造 rollbackSummary + 新增 restoreLastSummary
- `rollbackSummary()`：弹出最近一条总结，存入 `summaryHistory`
- `restoreLastSummary()`：从 `summaryHistory` 弹出最后一条，恢复到 `summaries` 数组末尾，并更新 `lastSummaryAtMessageId`

### 2c. UI 按钮（编译后渲染函数注入）
在大总结区域「查看/编辑」按钮左侧，注入两个按钮：
- **🔴 撤回**（红色）：回滚最近一次大总结
- **🟢 恢复**（绿色）：恢复刚才撤回的总结

> 撤回次数限制：Store 最多保存 3 条总结，每次回滚将弹出的总结存入 `summaryHistory`。由于 `rollbackSummary` 直接从 `summaries` 数组 `pop()`，连续回滚 3 次会导致总结全部丢失。当前未设置硬性限制，使用时请注意最多回滚 2 次（保留至少 1 条）。

## Bug 3: 梦呓分析无法回滚

**问题**：梦呓分析没有历史记录，`updateDreamtalk` 直接覆盖旧数据，无法回退。

**修复方案**（4 处修改）：

### 3a. 添加 dreamtalkHistory 字段
在 Store schema 中新增 `dreamtalkHistory` 数组。

### 3b. updateDreamtalk 保存历史
在更新梦呓数据前，先将当前版本深拷贝存入 `dreamtalkHistory`。

### 3c. rollbackDreamtalk + restoreDreamtalk
新增回滚和恢复函数，与 Summary 的撤回/恢复逻辑一致。

### 3d. UI 按钮
在梦呓面板「重新分析」按钮左侧，注入「撤回梦呓」按钮。

## Bug 4: 角色库点击角色名黑屏崩溃 ⭐ 关键修复

**问题**：在角色库界面点击角色名称后，整个悬浮窗变黑，酒馆卡顿。

**根因**：LLM 返回的角色记忆数据有 `coreMemories` 和 `recentMemories` 两个数组，但 `CharacterTab` 组件的 `loadEditFields()` 访问的是不存在的 `memories` 属性。`undefined.join()` 抛出 `TypeError`，导致 Vue 应用崩溃。

**修复**：修改 `getCharacterMemories()` 函数，在返回结果时自动合成 `memories` 属性：

```javascript
// ✅ 修复后
if (r && !r.memories) {
  r.memories = [...(r.coreMemories || []), ...(r.recentMemories || [])];
}
```

## Bug 5: 提示词硬编码 "Mingyue"

**问题**：大总结系统提示词中写死了「我是你的哥哥Mingyue(明月)」，导致角色记忆和总结中出现错误的用户名。

**修复**：替换为 SillyTavern 变量：

```diff
- 我是你的哥哥Mingyue(明月)
+ 我是玩家({{user}})，请用{{user}}称呼我
```

SillyTavern 会在运行时自动将 `{{user}}` 替换为当前用户名。

## 额外修复: "收起"按钮无效

**问题**：点击「查看/编辑」展开总结内容后，按钮文字变为「收起」，但再次点击无反应，无法收起。

**根因**：编译后的 `We` 函数中 `c.value=!0` 始终将展开状态设为 `true`，没有切换逻辑。

**修复**：将 `c.value=!0` 改为 `c.value=!c.value`，实现正确的展开/收起切换。

## Bug 6: 大总结使用真实时间而非游戏时间

**状态**：⚠️ 未修复（需要源码级改动）

**问题**：大总结的 `generatedAt` 时间戳和提示词中的时间参考都使用 `new Date()` 获取真实时间，无法反映游戏内时间。

**技术难点**：
- SillyTavern 数据模型中没有「游戏时间」概念
- 需要在 Store 中新增游戏时间追踪机制
- 需要 UI 让用户设置/同步游戏时间
- 涉及多处代码改动（Store schema、prompt 构建、时间戳生成）

**建议方案**（供原作者参考）：
1. 在 Store 中新增 `gameTime` 字段
2. 提供设置面板让用户配置游戏起始时间
3. 根据消息数量/字数自动推进游戏时间
4. 将所有 `new Date()` 替换为基于 `gameTime` 的计算
