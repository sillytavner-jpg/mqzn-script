{user}：秋青子，现在需要你执行一项场景切分任务。这不是创作，是结构化数据整理。

## 任务说明

我会给你一段原始聊天（最近若干楼，每条带稳定 messageId 标记）。请你判断这一段里发生了几个"场景"，并标出每个场景的边界与状态。

你必须先在<thinking></thinking>中按下方"切分判断体系"逐步分析，再在</thinking>后的<content>标签内输出正式 JSON 结果。

## 切分判断体系（必须严格按此执行）

### 一、什么是"一个场景"（切分粒度）
按"叙事单元"切分，不按物理小动作切分。
- 一个场景 = 一段围绕同一主导目的、在同一核心地点、由同一核心参与群体推进的连续叙事。
- 反例（同一场景，不切）：主角在酒馆和老板谈了 10 轮，中间老板起身去倒了杯茶又坐回来继续谈 —— 倒茶是场景内的小动作，主导目的（谈银钥匙买卖）没变，仍是 1 个场景。
- 正例（切分）：谈完买卖，二人走出酒馆到了后院，开始盘问小偷 —— 地点+参与者+事件性质都变了，从这一刻起是新场景。
- 判定口诀：切分看"读者追踪的那条主线是否切换"，不看"角色有没有起身做件小事"。

### 二、切分信号（综合判断，不单看一个）
出现以下任一信号且导致"主导叙事主线切换"时，视为场景边界：
1. 地点变了：叙事焦点随角色移动到新地点（酒馆→后院）。
2. 时间跳了：故事时间明显跳跃（"白天"→"三天后"/"次日清晨"），且叙事当作新起点。
3. 参与者变了：核心在场群体实质改变（刚才和老板谈，现在和小偷打）。
4. 事件性质变了：同地点同人，但主导事件性质切换（闲聊→打架 / 谈判→偷袭）。
5. 叙事节奏/主题断了：一段紧凑主线中插入大段无关内容（谈判中插大段毫不相干的内心独白/插叙），导致主线被截断，可拆。

注意：以上信号必须造成"主导叙事主线切换"才切分。仅轻微信号（短暂离场取物又回、次要旁观者进出）不切分。

### 三、状态判定（进行中 / 已结束）
- 默认：窗口中"最后一段"为"进行中"（保持原文，不压缩）。只有明确闭合的才算"已结束"。
- "已结束"的明确信号（满足任一）：
  a. 话题完成且角色离散：本次主线目的达成/失败，相关角色离场或转入无关活动；
  b. 明确的时空跳跃已发生且该场景未被延续（"那一夜过后，众人散去"类收束）；
  c. 该窗口内其后已开启了一个新场景（则前一个自然结束）；
  d. 叙事显式收束该线程（淡出/转场/"此后很久没有他的消息"）。
- 严禁仅因"地点变了"就判旧场景结束——若角色离开又回来且主线未断，仍属同一场景（倒茶原则）。
- 若窗口末尾主线仍在进行、无闭合信号 → 状态="进行中"。

### 四、边界粒度（跨楼层与同楼多场景）
- 边界以 messageId 为最小粒度，不是楼层粒度。
- 一个场景可跨多楼层：floorStart != floorEnd（如占第 3–8 楼）。
- 同一楼层内可有两个场景：用 messageId 子范围区分（两个 segment 的 floorStart==floorEnd，但 messageIdStart/End 不同）。
- 必须满足：所有 segment 的 [messageIdStart, messageIdEnd] 连续且无遗漏地覆盖本窗口全部 messageId。

## 输出格式（严格遵循，输出合法 JSON）

在</thinking>后，你必须在<content>标签内输出如下 JSON（可被程序直接解析）：

{
  "segments": [
    {
      "segmentIndex": 1,
      "messageIdStart": 0,
      "messageIdEnd": 0,
      "floorStart": 0,
      "floorEnd": 0,
      "location": "酒馆大堂",
      "participants": ["主角", "酒馆老板"],
      "storyTime": "白天（若原文无明确时间写'未明'）",
      "sceneId": "",
      "status": "进行中",
      "summary": "主角在酒馆和老板谈银钥匙的买卖",
      "splitReason": "单场景/或说明边界信号：地点+参与者变化"
    }
  ],
  "reasoning": "简要说明整体切分与状态判断依据"
}

字段规则：
- sceneId：若 {airpSceneHints} 已提供某段消息的 AIRP 场景 ID，则原样填入该 segment；否则留空字符串""，由代码补全。
- status 枚举："进行中" | "已结束"。
- summary：一句话场景摘要，客观白描，含"谁+在哪+做了什么"。
- 若整段是单场景，segments 只含 1 个元素，但其 messageIdStart/End 仍须覆盖整个输入窗口。

## 铁律

- 只基于提供的原文判断，禁止创作原文没有的地点/人物/事件。
- 禁止把同一主导叙事拆成多个 segment（倒茶原则）。
- 禁止遗漏或重叠 messageId 范围；必须完整覆盖输入窗口。
- 正在进行的场景状态必须标"进行中"，不得提前压缩。
- 所有 segment 的 storyTime/location/participants 必须能在原文中找到依据。
